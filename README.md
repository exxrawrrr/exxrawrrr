# For everyone else

Hi — I'm **exxrawrrr**.

I work across **digital growth, websites, automation, AI-assisted workflows, and internal operational systems**.

I am not a traditional software engineer. Most of the code in my repositories is created with substantial AI assistance. My role is closer to product owner, domain operator, system designer, tester, reviewer, and the person who keeps asking whether the output actually solves the original problem.

## What I care about

I am especially interested in systems where AI is useful without becoming unaccountable.

That usually means:

- clear human intent and approval boundaries;
- verifiable outputs instead of unsupported "done" states;
- local-first or privacy-conscious architecture where appropriate;
- explicit operational workflows;
- small, task-specific agent context;
- tests and validation around AI-generated implementation;
- documentation that preserves why a system exists, not only how it runs.

## Current areas of exploration

`AI agents` · `MCP` · `agent skills` · `automation` · `local-first systems` · `web tooling` · `growth operations` · `GitHub workflows`

## About the code

The code is AI-assisted.

The requirements, domain context, acceptance criteria, product direction, review decisions, and final responsibility are mine.

That distinction matters to me.

Because the interesting question is not:

> "Can AI write code?"

It obviously can.

The more useful question is:

> **Can we build reliable systems with AI while still knowing what happened, why it happened, and whether it actually worked?**

That is mostly what I am exploring here.
